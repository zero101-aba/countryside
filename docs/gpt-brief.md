# 给 ChatGPT 的项目 Brief（直接整段复制粘贴）

你好，我在做一个手机端的像素风种田小游戏《田园小镇》，已经有可玩原型，想请你帮我做**内容扩展 + 优化方向**。请不要从零重写，只给增量方案。

## 游戏一句话

玩家是"东家"，给村民下指令，村民按自己的性格、情绪和需求自己走过去干活，玩家全程看得见；村民会饿、会累、会生气、会聊天。

## 技术栈与约束

- 纯前端：HTML + CSS + 原生 ES Module + Canvas 2D，无框架、无构建、无后端、无外部美术素材
- 所有像素图形都是代码程序化绘制（矩形/路径）
- 手机竖屏与横屏都要支持；横屏为「左侧游戏 + 右侧村民栏」
- 存档用 localStorage
- 文件结构：config.js（数值）、world.js（地图生成）、sprites.js（角色像素绘制）、emotions.js（情绪）、dialogue.js（对话引擎）、villagers.js（村民 AI/任务）、sim.js（模拟核心）、renderer.js（渲染）、ui.js（DOM 界面）、game.js（主循环/输入）

## 已有系统

- 地图 40×30：村庄、农田、集市、水井、河流、池塘、果园、谷仓、鸡圈、风车、营地、围栏、路灯/花坛/长椅等
- 6 个村民（小伟、小杨、阿福、小满、铁柱、春杏）+ 2 个可雇佣角色，各有外观、性格、喜好、情绪基线
- 情绪：喜悦/恼火/低落/不安/疲惫 + 信任；会影响干活速度、是否拒绝指令、说话语气
- 对话：9 个话题 + 自由输入关键词意图识别；回答由情绪、性格、上下文组合；有记忆、会被刷屏惹烦
- 指令：开垦/播种/浇水/收获/砍树/钓鱼/采集/休息/聊天；A* 寻路；工作动画、粒子、进度环、目标连线
- 时间：1 游戏小时 = 5 秒（一天约 2 分钟）；四季；5 种作物；只在湿润时生长
- 经济：买种子/卖仓库/买面包/雇人；收获可自动出售
- 表现：昼夜光照、路灯/窗户/篝火暖光、季节粒子、每名村民头顶实时对话气泡
- 新手引导、目标链、存档

## 我希望你输出什么（按这个顺序）

### 1. 新地图（3~4 个，最重要）

每个地图给出：
- 主题与视觉基调（例如：河边渔村 / 山林矿洞 / 集市小镇 / 废弃农庄）
- 尺寸与进入方式（走路切换场景 / 地图边缘 / 建筑入口）
- 用 ASCII 或坐标网格画出布局（地块、水、建筑、路径、资源点）
- 与主村庄的资源/经济循环如何连接（例如矿洞出矿石、渔村出鱼、林场出木头）
- 新玩法差异（该地图特有的指令、作物、事件、危险）
- 实现难度评估与最小可行版本（MVP）

### 2. 新功能（8~10 个）

每个功能给出：目标、玩家操作流程、系统规则、UI 呈现、数值建议、实现要点、优先级。可以包括但不限于：
- 任务委托板（每日刷新）
- 村民关系/好感/事件
- 养殖（鸡/牛）与动物产品
- 建造与升级（鸡舍、谷仓、作坊）
- 加工/烹饪（把作物变成高价商品）
- 节日与季节事件
- 雨天/天气系统（影响浇水与情绪）
- 收集图鉴/成就
- 多地图旅行与体力/时间成本
- 手机端快捷指令（一键派活、队列、优先级）

### 3. 优化方向

- 性能（Canvas 分层、缓存、每帧开销）
- 操作与信息密度（尤其手机横屏/竖屏）
- 新手节奏与留存（前 10 分钟、第一天、第一周）
- 内容节奏（一天 2 分钟是否合适；季节长度）
- 代码结构与可扩展性（数据驱动、地图配置化）
- 哪些现有系统应该砍掉或简化

### 4. 角色模型丰富方案

当前每个角色是 22×22 的程序化像素小人，有 4 方向、走路/干活帧。请给出：
- 一套像素角色可组合的部件清单（发型、刘海、胡子、服装、外套、围裙、眼镜、耳饰、帽子、背包、靴子、肤色）
- 每个现有角色适合的部件组合（体现性格/职业）
- 动作与表情扩展（眨眼、呼吸、擦汗、打招呼、生气跺脚、坐下休息）
- 在不换引擎、不加素材的前提下，性价比最高的 5 个改动
- 角色差异化清单（避免看起来像同一个人）

### 5. 取舍建议

- 如果只能做 3 件事让游戏"更完整"，你会选哪三件？为什么？
- 哪些想法听起来好但会拖垮这个体量的项目？

## 输出格式

用中文，Markdown。先给「一页纸路线图」，再按上面 5 部分展开。每个功能都标注 **S/M/L** 工作量和优先级 P0/P1/P2。不要写代码，先给设计和取舍。
